# Agent accounts and provider rules

Checked **2026-11-27**. Dates in the table are the dates on the source pages. The account owner is responsible for the work they send and the terms of their plan. Use a separate sign-in for each person. Every task, reviewer and scheduled run uses the agent's normal allowance and may incur charges.

## Provider rules

[Automation docs](https://learn.chatgpt.com/docs/non-interactive-mode) recommend API keys for most CI and document when to use Codex user auth on trusted runners. [Enterprise access tokens](https://learn.chatgpt.com/docs/enterprise/access-tokens) require admin permission. | The official CLI on the user's machine. ## Code paths checked

**Explicit** means the provider documents the operation. **Clear implication** means Shepherdr uses the documented command or displays the person's own local data through their terminal. The findings apply to this checkout and the normal user-owned installation.

| Path | Finding and code |
| --- | --- |
| Starts, resumes, sends, keys, screens and sign-in | **Explicit** CLI starts, resume, login/status, and control through the official CLIs ([Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference)). **Clear implication** for terminal hosting and relaying input the person supplies. Shepherdr uses [herdr-core](https://github.com/herdrdev/herdr-core/blob/master/docs/commands.md) for processes, input, status, screens and commands on linked machines. See `launch.py`, `takeover.py`, `service/actions.ts`, `service/hub.ts`, `service/watch.ts` and `core/screens.js`. The checked-in sign-in surface is the provider's CLI prompt and its terminal link. A separate sign-in helper was outside this checkout. |
| Transcript, context and token estimates | **Clear implication** for reading user-owned local session logs on their machines. The providers document reading conversations through [Claude SDK session methods](https://code.claude.com/docs/en/agent-sdk/typescript#getsessionmessages) and [Codex `thread/read`](https://learn.chatgpt.com/docs/app-server). `core/chat-reader.js`, `core/chat-log.js` and the task session reader adapt local files for already-running terminals. File layout is an implementation detail and can break as CLIs update. Usage insights are Shepherdr's own task events. Context is reported or estimated from turns, separate from a billing or quota figure. |
| Subscription limits and model lists | **Explicit** Codex App Server rate limits and model listing, and ElevenLabs subscription usage. **Unclear and removed** Claude `/usage` in a background print process, Claude Keychain extraction and credential copying, Codex auth-file inspection and temporary credential mounts, the Claude private model handshake, and Codex debug/cache model probes. See `machine.py`, `service/machines.ts`, `service/agents.ts` and `settings.py`. There is no documented herdr-core quota/catalog operation. |
| Model, reasoning, speed and updates | **Explicit** published model, effort and speed options ([Claude](https://code.claude.com/docs/en/model-config), [OpenAI](https://learn.chatgpt.com/docs/agent-configuration/speed)) and the providers' own CLI updates. **Clear implication** for sending the person's pick to the CLI's own commands or restarting with its documented settings. See `core/agents.js`, `core/live-switch.js`, `settings.py` and `service/agent-update.ts`. Claude's menu uses published models. Claude's own `/model` knows the current list for the account. The CLI decides what the account and workspace can use. |
| Approvals, trust and reviews | **Explicit** [Claude permissions and hooks](https://code.claude.com/docs/en/permissions), [Codex hooks](https://learn.chatgpt.com/docs/hooks) and its [automatic review](https://learn.chatgpt.com/docs/sandboxing/auto-review). The person can answer the request in the UI. Where selected, the CLI applies its own Auto or Approve for me mode. Hooks can allow a short list of Shepherdr commands. **Unclear and removed** injecting trust for repositories and writing synthetic trust hashes for hooks. Use the CLI's trust prompt or `/hooks`. The worker brief leaves a reviewer's startup trust and sign-in prompts for the person. See `launch.py`, `settings.py`, `templates/worker.md`, `hooks/` and `service/asks.ts`. |
| Parallel tasks, schedules and linked machines | **Clear implication** for multiple ordinary sessions started by the same user on their own devices, within the provider's allowance. The providers document concurrent tasks, automation and read-only work ([Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview), [Codex app](https://openai.com/index/introducing-the-codex-app/), [Codex automation](https://learn.chatgpt.com/docs/non-interactive-mode)). No fixed cross-plan session count was found. Each machine signs in separately, and the CLI enforces account, workspace, quota and speed entitlements. Shepherdr does not rotate logins, pool accounts or retry a refused task with a different agent. Schedules and delayed starts use Claude Code or Codex. A reported quota, rate, sign-in or general provider denial pauses its recurring schedule. See `commands.py`, `automations.py`, `tick.py`, `provider.py`, and `service/actions.ts`. |
| Phone, watch and voice | **Clear implication** for clients invoking the same local app actions and showing the same data. Native chat and glance share the web service's paths. **Explicit** for ElevenLabs API calls, including the optional voice and dictation routes. See `service/native-chat.ts`, `service/glance.ts`, `service/voice.ts`, `service/voice-tools.ts`, `service/voice-data.ts` and `service/dictate.ts`. The standalone native app is outside this repo. |

## What the Antigravity reports show

- **2026-02-11.** OpenClaw users reported Antigravity and Gemini CLI access disabled after using their Google OAuth through OpenClaw. **2026-02-27.** Google's Gemini CLI team confirmed an enforcement reset and described reinstatement and how repeat violations would be handled. The relevant service access was Antigravity and Gemini CLI. These sources do not establish a blanket ban on a user's entire Google account. [OpenClaw report](https://github.com/openclaw/openclaw/issues/14203) · [Google statement](https://github.com/google-gemini/gemini-cli/discussions/20632)
- **2026-10-30.** A T3 Code report shows its Antigravity quota checker used backend quota/model methods outside the published CLI or ACP docs. It is evidence of the quota-check route, with no verified ban from that request alone. **2026-11-21.** Google staff publicly discussed use of the official Antigravity ACP agent in T3 Code. That is separate from an independent quota call. Google’s published FAQ and terms govern other clients and auth methods. [T3 Code report](https://github.com/pingdotgg/t3code/issues/27473) · [Google staff statement](https://x.com/PatrickToulme/status/2124265732540387418) · [Antigravity FAQ](https://antigravity.google/docs/faq)
- For a new integration, a managed deployment, or a workspace contract with different limits, confirm the exact setup with [Anthropic](https://support.claude.com/), [OpenAI](https://help.openai.com/), [Cursor](https://cursor.com/contact), [Google Antigravity](https://discuss.ai.google.dev/c/antigravity/64), or [ElevenLabs](https://help.elevenlabs.io/). Recheck the relevant dated row when a provider changes its auth, plans or terms.
