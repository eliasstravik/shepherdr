# Agent accounts and provider rules

Checked **2026-11-27**, then again the same day with a stricter bar: anything a provider's own terms or docs don't explicitly allow, or that carries even the slightest doubt, is removed (see [Second pass](#second-pass-2026-11-27)). Dates in the table are the dates on the source pages. The account owner is responsible for the work they send and the terms of their plan. Use a separate sign-in for each person. Every task, reviewer and scheduled run uses the agent's normal allowance and may incur charges.

## Code paths checked

**Explicit** means the provider documents the operation. **Clear implication** means Shepherdr uses the documented command or displays the person's own local data through their terminal. The findings apply to this checkout and the normal user-owned installation.

| Path | Finding and code |
| --- | --- |
| Starts, resumes, sends, keys, screens and sign-in | **Explicit** CLI starts, resume, login/status, and control through the official CLIs ([Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference)). herdr-core, the base Shepherdr runs on, hosts the terminals and relays the input the person supplies. Shepherdr uses [herdr-core](https://github.com/herdrdev/herdr-core/blob/master/docs/commands.md) for processes, input, status, screens and commands on linked machines. See `launch.py`, `takeover.py`, `service/actions.ts`, `service/hub.ts`, `service/watch.ts` and `core/screens.js`. Shepherdr routes chat messages to Assistants and task agents through herdr-core and never presses keys in an agent's menus or prompts on its own. For Codex, the 2026-11-27 check uses only `codex login status` and keeps the sign-in result, including the API-key status, without keeping raw output or reading Codex settings or credentials. If Shepherdr changes the reviewer because it cannot confirm sign-in, the task card says so. When an agent needs signing in, its card names the CLI's own command (`/login`, `/mcp`, `codex login`, `codex login --device-auth`, `codex mcp login`) and opens its terminal; the person signs in there. See `service/sign-in.ts` and `service/sign-in-screen.ts`. |
| Transcript, context and token estimates | **No provider contact**: reading user-owned local session logs on their machines makes no request to any provider and uses no sign-in. The providers document reading conversations through [Claude SDK session methods](https://code.claude.com/docs/en/agent-sdk/typescript#getsessionmessages) and [Codex `thread/read`](https://learn.chatgpt.com/docs/app-server). `core/chat-reader.js`, `core/chat-log.js` and the task session reader adapt local files for already-running terminals. File layout is an implementation detail and can break as CLIs update. Usage insights are Shepherdr's own task events. Context is reported or estimated from turns, separate from a billing or quota figure. |
| Alert routing and waiting status | **No provider contact** (checked 2026-11-27). Shepherdr keeps Monitor notices in local task logs out of the person's messages. Its existing local status and question cards drive alerts and tell the space's Assistant when a wait clears. |
| Subscription limits and model lists | **Explicit** ElevenLabs subscription usage, with the person's own key ([API](https://elevenlabs.io/docs/api-reference/user/subscription/get)). **Removed** every Claude and Codex usage or limit read: Claude `/usage` in a background print process, Claude Keychain extraction and credential copying, Codex auth-file inspection and temporary credential mounts, the Claude private model handshake, Codex debug/cache model probes (first pass), and Codex App Server `account/read`, `account/rateLimits/read` and `model/list` (second pass). Settings and each machine's card say where to look: `/usage` in Claude Code, `/status` in Codex. Model menus are the providers' published lists. See `machine.py`, `service/machines.ts`, `core/agents.js` and `web/src/settings.tsx`. herdr-core has no quota or catalog operation. |
| Model, reasoning, speed and updates | **Explicit** published model, effort and speed options ([Claude](https://code.claude.com/docs/en/model-config), [OpenAI](https://learn.chatgpt.com/docs/agent-configuration/speed)), resuming a conversation with documented flags ([Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference)) and the providers' own CLI updates. A pick restarts the agent on the same conversation with those flags. **Removed** (second pass) switching in place by typing `/model`, `/effort`, `/fast` into the agent and stepping through its menus from screen reads, then rewriting its settings files. See `core/agents.js`, `service/agents.ts`, `settings.py` and `service/agent-update.ts`. The CLI decides what the account and workspace can use. |
| Approvals, trust and reviews | **Explicit** [Claude permissions and hooks](https://code.claude.com/docs/en/permissions), [Codex hooks](https://learn.chatgpt.com/docs/hooks) and its [automatic review](https://learn.chatgpt.com/docs/sandboxing/auto-review). The person can answer the request in the UI. Where selected, the CLI applies its own Auto or Approve for me mode. Hooks can allow a short list of Shepherdr commands. **Unclear and removed** injecting trust for repositories and writing synthetic trust hashes for hooks. **Removed** (second pass) answering a CLI's trust or start screens from the app, a worker pressing keys on its reviewer's screens, and pre-trusting a Codex reviewer with `-c projects`. The person answers the CLI's trust prompt in its terminal, or uses `/hooks`. Checked 2026-11-27 against [Codex 0.172.0 hook discovery](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/hooks/src/engine/discovery.rs). The documented `-c` override uses a stable hook command and timeout. The launch passes its review mode in the environment. Startup and blocking dialog cards show the visible choices and open the terminal for the person to answer. Codex Auto keeps workspace writes and on-request approval. Full access is explicitly selected and matches Codex's danger-full-access mode with approvals off. See `launch.py`, `core/screens.js`, `service/watch.ts` and `service/asks.ts`. |
| Parallel tasks, schedules and linked machines | **Clear implication** for multiple ordinary sessions started by the same user on their own devices, within the provider's allowance. The providers document concurrent tasks, automation and read-only work ([Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview), [Codex app](https://openai.com/index/introducing-the-codex-app/), [Codex automation](https://learn.chatgpt.com/docs/non-interactive-mode)). [OpenAI's usage guide](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits) explains plan limits. No fixed cross-plan session count was found. Each machine signs in separately, and the CLI enforces account, workspace, quota and speed entitlements. Shepherdr does not rotate logins, pool accounts or retry a refused task with a different agent. Schedules and delayed starts use Claude Code or Codex. Task Agent and Reviewer settings only accept these known CLIs (checked 2026-11-27). A reported quota, rate, sign-in or general provider denial pauses its recurring schedule. See `commands.py`, `automations.py`, `tick.py`, `provider.py`, and `service/actions.ts`. |
| Phone, watch and voice | **Clear implication** for clients invoking the same local app actions and showing the same data. Native chat and glance share the web service's paths. **Explicit** for ElevenLabs API calls, including the optional voice and dictation routes. See `service/native-chat.ts`, `service/glance.ts`, `service/voice.ts`, `service/voice-tools.ts`, `service/voice-data.ts` and `service/dictate.ts`. The standalone native app is outside this repo. |

## Second pass (2026-11-27)

The bar: anything not explicitly allowed by the provider's own terms or docs, or with the slightest doubt, goes, however useful.

**Removed**

- Codex plan usage and limits (App Server `account/read` and `account/rateLimits/read`). Usage warnings and the phone, watch and voice usage lines now only show ElevenLabs, read with the person's own API key.
- Codex's model list from the App Server (`model/list`), and the reviewer-model check that used it. The menu shows OpenAI's published models; Codex itself refuses one the account can't use.
- Switching a running agent's model, level or speed in place by typing its slash commands, driving its pickers from screen reads and rewriting `~/.claude/settings.json` or `~/.codex/config.toml` afterwards. A pick now restarts the agent on the same conversation with documented flags, and waits while a turn runs.
- Keys pressed into an agent on Shepherdr's own: Ctrl+Enter ("send now") and then Esc on a message sent mid-turn, Esc to close the agent's own question before typing a message, Enter/Tab after a send to Codex, and Ctrl+Enter on Shepherdr's own news and cross-machine messages. A send is now herdr-core's `send` alone; Claude Code queues a mid-turn message itself, Shepherdr's news waits until the agent is idle, and a message to an agent on its own question is refused ("answer that in its terminal first"). The unused Send now on a queued message went too.
- A worker pressing keys on its reviewer's trust or sign-in screen (`hc keys` in a worker's reviewer allowlist). The worker now tells the person to answer it in the reviewer's terminal.
- Sign in from the app: typing `/login` or `/mcp` into Claude Code, stepping its menu and pasting its code back; running `codex login`, `codex login --device-auth`, `codex mcp login` or `codex login --with-api-key` for the person and keeping a copy of their OpenAI key. The card now names the command to run and opens the agent's terminal.
- Answering for the person by pressing keys on the agent's screen, even on a tap: Codex's questions (`request_user_input` and its queued questions), a CLI's start screens and its folder-trust screen ("Trust this folder and start"), and Rewind (typed `/rewind` and stepped its list). Each card now says what it asks and opens the terminal to answer there. Claude Code's hook asks keep their buttons: those answers go back through its documented hooks.
- Extra Enter presses when a message stayed in Claude Code's box after a send (up to five). Shepherdr only watches; a message still there shows as stuck and the person's Retry presses its Enter.
- A Codex reviewer pre-trusted with `-c projects=…` in the worker's reviewer allowlist.
- Automatic recaps (a `<herdr-recap>` prompt sent when the person came back to a chat) and their Settings › Recaps switch. Recap in a chat's menu, the person's own ask, stays.

**Kept, and why**

- Starts, resumes and sign-in status through the official CLIs' documented commands and flags (`--resume`, `codex resume`, `claude auth status`, `codex login status`). The person signs in themselves, in the agent's terminal.
- The person's own keys, sends and Stop, passed through herdr-core as they typed or tapped them.
- Automatic prompts to Claude Code and Codex (tasks, schedules, the Assistant's news). Anthropic's [plan guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) allows automated Claude Code use on a plan, and OpenAI's [automation docs](https://learn.chatgpt.com/docs/non-interactive-mode) cover Codex user auth on trusted runners. The requests are the official CLI's own.
- Reading local session logs, which contacts no provider.
- ElevenLabs calls with the person's own key, all through public APIs.

**In herdr-core itself (not Shepherdr's to change)**

herdr-core is the base Shepherdr runs on, and its own behaviour is taken as fine. Shepherdr uses it for terminals, starts, sends, keys, screens and status instead of its own. Worth knowing:

- `hc --skill` suggests `pi --provider openai-codex` as a helper. That runs a third-party client on a ChatGPT sign-in, which OpenAI's App Server and Sign in with ChatGPT docs don't allow for every app. Shepherdr never starts it.
- By default (`notes = true`) herdr-core types notes about child terminals into a parent agent's input. That is program-typed input into an interactive CLI, which neither provider documents for scripting. Setting `notes = false` in `~/.config/herdr-core/config.toml` turns it off; workers' reviewers and helpers report back through those notes, so turning them off changes how tasks wait on them.
- herdr-core decides whether an agent is working by reading its screen, and its `keys` and `send` type into the agent like a person would. No request leaves the official CLI.

## What the Antigravity reports show

- **2026-02-11.** OpenClaw users reported Antigravity and Gemini CLI access disabled after using their Google OAuth through OpenClaw. **2026-02-27.** Google's Gemini CLI team confirmed an enforcement reset and described reinstatement and how repeat violations would be handled. The relevant service access was Antigravity and Gemini CLI. These sources do not establish a blanket ban on a user's entire Google account. [OpenClaw report](https://github.com/openclaw/openclaw/issues/14203) · [Google statement](https://github.com/google-gemini/gemini-cli/discussions/20632)
- **2026-10-30.** A T3 Code report shows its Antigravity quota checker used backend quota/model methods outside the published CLI or ACP docs. It is evidence of the quota-check route, with no verified ban from that request alone. **2026-11-21.** Google staff publicly discussed use of the official Antigravity ACP agent in T3 Code. That is separate from an independent quota call. Google’s published FAQ and terms govern other clients and auth methods. [T3 Code report](https://github.com/pingdotgg/t3code/issues/27473) · [Google staff statement](https://x.com/PatrickToulme/status/2124265732540387418) · [Antigravity FAQ](https://antigravity.google/docs/faq)
- For a new integration, a managed deployment, or a workspace contract with different limits, confirm the exact setup with [Anthropic](https://support.claude.com/), [OpenAI](https://help.openai.com/), [Cursor](https://cursor.com/contact), [Google Antigravity](https://discuss.ai.google.dev/c/antigravity/64), or [ElevenLabs](https://help.elevenlabs.io/). Recheck the relevant dated row when a provider changes its auth, plans or terms.
